<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| unfurl bot to `/og` | `report`, `fight` and `source` are fully attacker-controlled on a public route |
| `/og` to `/api/analyze` and `/api/report` | two server-to-server fetches on the shared `anon` rate-limit identity |
| browser to clipboard and to PostHog | the copied URL and the event properties are built client-side from component props |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-10 | Tampering | `fight` and `source` params on the player branch | medium | mitigate | The existing integer-and-non-negative parse is unchanged and still runs before any fetch; the added report-meta fetch uses the same already-validated report code |
| T-03-11 | Denial of Service | the player branch now issuing two fetches per unfurl | low | accept | Both run in one `Promise.all` so no serial latency is added; `/api/report` has the highest rate-limit budget in the system and `fetchJson` degrades to null on a 429, leaving the existing fallback intact |
| T-03-12 | Information Disclosure | a player-specific card for a private or errored report | medium | mitigate | `/api/analyze` returns no `playerName` for a report that does not resolve publicly, so the branch falls through to the branded card; in-app, the scorecard only renders once an analysis loaded, so a failed report shows no share button |
| T-03-13 | Spoofing | the origin used to build the copied permalink | low | mitigate | `buildPlayerShareUrl` takes the origin explicitly from `window.location.origin` at the call site; the builder itself never reads a global, so a test pins the exact output |
| T-03-SC | Tampering | npm/pip/cargo installs | high | mitigate | No packages are added by this phase (RESEARCH `## Package Legitimacy Audit`: zero new dependencies). Any install would require a package-legitimacy gate plus a blocking human checkpoint first |
</threat_model>
