<objective>
Make light mode a genuine ParseForge first impression rather than an unstyled fallback: replace the
never-designed stock shadcn `:root` values with a brand-tuned light palette (D-09), add the missing
Tailwind v4 `@theme` token categories DSGN-01 requires (spacing, motion, elevation), and de-hardcode
the utility classes that currently bake dark-theme colours into their declarations.

Purpose: D-08 sends OS-light visitors straight into light mode on day one, so light can no longer be
the theme nobody designed. This plan is also where DSGN-01's "missing token categories added" half
lands; the "hardcoded values consolidated" half follows in plans 01-05 and 01-06.

Output: `scripts/theme-parity.mjs` as a standing gate, plus an `app/globals.css` where both themes
resolve every colour, spacing, motion and elevation value from a token.
</objective>

    Create `scripts/theme-parity.mjs`, a plain ESM node script (the repo is ESM-friendly; use
    `node:fs` and `node:process` imports) that reads `app/globals.css` relative to the repo root and:

    1. Extracts the custom properties declared inside the top-level `:root { ... }` block and inside
       the top-level `.dark { ... }` block into two maps of property name to declared value.
    2. Hard-fails with a clear message if either block cannot be located — an unparseable stylesheet
       must never produce a silent pass.
    3. **Parity check:** every property declared in `.dark` must also be declared in `:root`. Report
       any that are missing.
    4. **Divergence check:** for a `THEME_DIVERGENT` allow-list of property names, the declared value
       in `:root` must differ from the declared value in `.dark`. Seed the list with
       `--background`, `--foreground`, `--card`, `--card-foreground`, `--popover`,
       `--popover-foreground`, `--primary`, `--primary-foreground`, `--secondary`,
       `--secondary-foreground`, `--muted`, `--muted-foreground`, `--accent`, `--accent-foreground`,
       `--destructive`, `--border`, `--input`, `--ring`, `--sidebar`, `--sidebar-foreground`,
       `--sidebar-primary`, `--sidebar-accent`, `--sidebar-border`, `--sidebar-ring`,
       `--gold-from`, `--gold-to`, `--arcane-from`, `--arcane-to`, `--glow-gold`, `--glow-arcane`,
       `--surface-0`, `--surface-1`, `--surface-2`, `--surface-3`, `--status-good`, `--status-warn`,
       `--status-bad`, `--status-info`. A property in the list that is absent from either block is a
       parity failure, not a silent skip.
    5. Supports two modes: default mode prints every violation and exits 1 when there is at least
       one; `--report` mode prints the same findings, prefixes each divergence violation with
       `SAME IN BOTH: ` and always exits 0. `--report` is the inspection mode; default is the gate.

    Add `"theme-parity": "node scripts/theme-parity.mjs"` to `package.json` `scripts`, beside the
    existing `test` entry.

    Run `npm run theme-parity -- --report` against the stylesheet as it stands. It must list the
    brand tokens that are currently identical in both blocks — that output is the machine-proof that
    the gate has teeth before any value is edited, and it is also the exact worklist for Task 2.
    Record that list in the SUMMARY.
