# Phase 2.1: PostHog Consent Gate Hotfix - Context

**Gathered:** 2026-09-14
**Status:** Ready for planning
**Origin:** Urgent insertion (INSERTED after Phase 2). Decisions below were made by the developer in-session on 2026-09-14 after the diagnosis in `02.1-DIAGNOSIS.md`; there was no separate discuss-phase.

<domain>
## Phase Boundary

PostHog capture on parseforge.gg has been ~99.9% down since the Phase 1 prod deploy (2026-09-06). Root cause (confirmed three ways — see `02.1-DIAGNOSIS.md`): `PostHogProvider.tsx` sets `cookieless_mode: "on_reject"`, and in posthog-js 1.360 that makes consent **PENDING ⇒ every `capture()` dropped**; capture only resumes after `opt_in_capturing()`, which the provider calls solely from the `__tcfapi` callback — and Google's CMP never calls back for fresh visitors. This phase delivers: (1) **server-side geo classification** so non-consent-region visitors are opted in immediately with no CMP dependency; (2) **unchanged EEA/UK consent semantics** (no capture before the TCF dialog resolves, cookieless on explicit reject, replay only on full opt-in); (3) **measurability of the gate itself** — every event carries which consent path admitted it; (4) **OPS-01 hardened** so the ship gate requires a post-deploy live-traffic check and can never again pass on pre-deploy data; (5) honest retro addenda to the Phase 1 and Phase 2 verification records.

Out of scope: any ad code (Phase 4), changing the CMP vendor or its message config, CSP enforcing (Phase 7), the analysis engines, the PostHog MCP connector's default project (manual follow-up), the pre-existing GSC "Crawled – currently not indexed" investigation (Phase 3 gate), and the Vercel CLI account mismatch on the developer's machine (manual; blocks deploys, not code).

</domain>

<decisions>
## Implementation Decisions

### Where the region decision is made (SC 1)
- **D-01:** The consent-region decision is made **server-side from Vercel's geo request headers** (`x-vercel-ip-country`, ISO 3166-1 alpha-2), never from the client, never from `__tcfapi`. The client receives a single boolean, `isConsentRegion`, before `posthog.init` runs. — **Reversibility:** reversible.
- **D-02:** **Hard constraint on transport:** delivering that boolean must **not change the rendering mode of any route** — `/` stays ISR (`revalidate = 3600`), `/guides/*`, `/tbc-audit`, `/privacy`, `/terms` stay static, and no route gains a per-request server render it did not have. Calling `headers()` in `app/layout.tsx` is therefore **not acceptable** (it would make the whole tree dynamic). The transport is a research question (R-01) — the two candidates are a Next `proxy.ts`/middleware that classifies at the edge, or a minimal `/api/geo` endpoint the client calls once before init. Whatever is chosen must add at most one small request before the first capture and must **not set any cookie for a consent-region visitor before they consent**. — **Reversibility:** costly — the transport shape is what Phase 4's ad loader will read too.
- **D-03:** The consent-region set is **one exported constant in `lib/`** (e.g. `lib/geo.ts`) with a unit test, defined as **exactly the region set Google Privacy & Messaging's GDPR message is configured to target** (EEA + UK, and Switzerland if Google includes it — research R-04 verifies). A mismatch in either direction is a bug: a country in the list without a CMP dialog would be dropped forever (today's bug in miniature); a country with a dialog but outside the list would be captured before consent. **Unknown or missing header ⇒ consent region** (fail closed), and when running on Vercel (`process.env.VERCEL` set) that case emits one `logEvent("geo_header_missing", …)` via `lib/observability.ts` so it is countable in Vercel logs.

### Client behaviour by region (SC 1, SC 2)
- **D-04:** **Non-consent-region visitors:** inside `posthog.init`'s `loaded` callback, call `ph.opt_in_capturing({ captureEventName: false })` (or the equivalent that suppresses the default `$opt_in` event) and `ph.startSessionRecording()` immediately — Phase 1 D-07 behaviour — with **no `startConsentListener` and no `__tcfapi` involvement at all**. The first `$pageview` must not be lost to ordering: research R-03 settles whether `PostHogPageView`'s capture can fire before `loaded` and, if so, the provider defers page-view capture until the consent path is resolved.
- **D-05:** **Consent-region visitors:** the existing TCF flow in `PostHogProvider.tsx` / `lib/consent.ts` is **kept exactly as-is** — `opt-in-full` → opt in + start replay; `cookieless` → nothing further (explicit reject captures cookieless via the SDK's `isExplicitlyOptedOut()` path); `pending` after `CMP_TIMEOUT_MS` → no capture. This hotfix does **not** try to make pre-choice EEA visitors capture cookieless (Phase 1 D-06's stated intent, which the SDK never honoured) — that is deferred, see `<deferred>`.
- **D-06:** The decision logic that maps `(isConsentRegion, ConsentAction)` → SDK calls is **extracted into a pure, unit-tested function in `lib/consent.ts`** (same style as `deriveConsentAction`), so the provider's `loaded` callback becomes a thin switch over its result. Tests live in `lib/consent.test.ts` (vitest, node env — the project has no React Testing Library and this phase does not add one).

### Measurability of the gate (SC 3)
- **D-07:** Every event carries a **`consent_gate_path` super property** registered on the client before/at opt-in, with values `geo-non-consent-region` | `tcf-accept` | `tcf-reject` | `tcf-timeout`. `consent_resolved` keeps `accepted` and `gdpr_applies`; `consent_unavailable` keeps `reason`. It is accepted that `consent_unavailable` and `tcf-timeout` remain **unobservable from PostHog** for a pending consent-region visitor (the SDK drops them) — the server-side `geo_header_missing` log and the Vercel-Analytics-vs-PostHog ratio (D-08) are the observability for that gap.

### OPS-01 hardening (SC 4)
- **D-08:** `docs/OPS-01-SHIP-GATE.md` gains a **mandatory post-deploy live-traffic check** that must be run and pasted as evidence before a gate is signed: within **60 minutes** of the prod deploy, PostHog project 337485 shows **≥ 20 `$pageview` events from ≥ 2 distinct non-consent-region `$geoip_country_code` values**, and the PostHog `$pageview` count is **≥ 50 % of Vercel Web Analytics page views** for the same window (Vercel Analytics is already mounted in `app/layout.tsx` and is independent of PostHog — it is the reference signal that would have exposed this outage on day one). A phase whose events cannot be observed (`no-data`) **fails** the gate; it may no longer be recorded as "recorded, not assumed". The check is expressed as an exact HogQL query in the doc (and, at Claude's discretion, a `scripts/posthog-live-check.mjs` that runs it with a personal API key from the environment — never committed).
- **D-09:** Append-only **addenda** to `.planning/phases/01-foundation-themes-consent/01-VERIFICATION.md` and `.planning/phases/02-accuracy-analysis-depth/02-VERIFICATION.md` (dated 2026-09-14) stating that their OPS-01 PostHog criterion was not met at sign-off and was met by Phase 2.1; `REQUIREMENTS.md`'s OPS-01 row gets the same note. Existing text is not rewritten.

### Verification and deploy (SC 1–4)
- **D-10:** The end-to-end proof for the tracer slice is the **same headless-Chrome netlog technique that found the bug**: a fresh profile loading the preview URL from a non-consent-region IP must produce a capture request to `/ingest/e/*` or `/ingest/i/v0/e/*` within ~5 s of load, whereas today it produces none. Record the exact command (with `--virtual-time-budget` and a hard timeout/kill — the bare command does not exit on its own) in the plan's verify block and in the OPS-01 doc.
- **D-11:** Ship **preview first** (`vercel deploy --scope loot-list-plus`), run D-10 against the preview, then **prod only after the developer's explicit confirmation** (CLAUDE.md). Note: the developer's machine is currently logged into the wrong Vercel team (`beast-app`); `vercel login` with the owning account is a prerequisite the plan must surface as a human checkpoint, not silently retry.

### Claude's Discretion
- Exact file layout (`lib/geo.ts` vs folding into `lib/consent.ts`), the name of the boolean prop, and whether the region constant is a `Set<string>` or a frozen array.
- The transport implementation details once R-01 picks proxy/middleware vs `/api/geo` (matcher scope, caching headers, response shape), within D-02's constraints.
- Whether to add `scripts/posthog-live-check.mjs` or keep the live check as a documented HogQL query run through the PostHog MCP.
- Wording of the OPS-01 doc changes and the verification addenda.
- Whether `consent_gate_path` is set with `posthog.register` or passed per-event — but it must be on every event, including `$pageview`.

<specifics>
## Specific Ideas

- The fix must be **small**: one config path change in the provider, one pure function, one region constant, one transport. If a plan grows past ~6 files of source change, something is wrong.
- The tracer slice is "a fresh US visitor's `$pageview` reaches PostHog on the preview deploy" — proven by netlog, not by reading code.
- The OPS-01 change is the durable half of this phase: a gate that accepts `no-data` is not a gate.
- Copy the exact SDK semantics into a comment above `cookieless_mode` so the next reader knows PENDING = dropped.

</specifics>

<deferred>
## Deferred Ideas

- **Cookieless capture for pre-choice consent-region visitors** (Phase 1 D-06's stated intent). posthog-js drops PENDING under `on_reject`; achieving cookieless pre-choice capture would need a different SDK mode or an explicit `opt_out_capturing()` on timeout. Revisit in Phase 4 alongside the ad consent signal, with legal review of cookieless analytics under ePrivacy.
- Making `consent_unavailable` observable (server beacon or cookieless send) — same dependency as above.
- Fixing the PostHog MCP connector's default project (LootList+ → ParseForge) — manual, outside the repo.
- Investigating whether Google Privacy & Messaging exposes `__tcfapi` for non-EEA visitors at all (R-04 answers it for this phase's purposes; the CMP config itself is not changed here).
