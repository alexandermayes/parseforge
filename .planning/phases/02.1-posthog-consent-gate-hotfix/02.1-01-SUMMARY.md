# Phase 2.1 Plan 01: PostHog Consent Gate Hotfix — Source Change Summary

**Server-side geo classification opts non-EEA/UK visitors in with no `__tcfapi` dependency; a pure `deriveConsentGateOutcome` function now decides both the geo and TCF paths, with the provider reduced to a single SDK-call executor.**

## Accomplishments
- `lib/geo.ts` / `lib/geo.test.ts`: `CONSENT_REGIONS` (32 ISO codes: EU-27 + IS/LI/NO + GB + CH) and `isConsentRegionCode`, fail-closed on nullish/blank/unknown input, trimmed case-insensitive comparison.
- `app/api/geo/route.ts` / `app/api/geo/route.test.ts`: the sole Route Handler reading `x-vercel-ip-country`; returns `{ isConsentRegion }` with `Cache-Control: private, no-store`, no cookie, `dynamic = "force-dynamic"`, and a `geo_header_missing` log on Vercel when the header is absent.
- `app/components/PostHogProvider.tsx`: `posthog.init` moved to module scope (eliminates the child-effect-before-parent-effect first-`$pageview` race); a `consentReady` gate defers `PostHogPageView`'s capture until the geo/TCF decision resolves; both paths now route through a single `applyOutcome` executor built on `deriveConsentGateOutcome`.
- `lib/consent.ts` / `lib/consent.test.ts`: new `ConsentGatePath` union, `ConsentGateOutcome` interface, and `deriveConsentGateOutcome(isConsentRegion, tcfAction)` — the pure merge of the two signals into SDK calls, with 10 new tests covering every outcome row plus the gatePath-literal and optIn/startReplay invariants. All 11 pre-existing `deriveConsentAction`/`startConsentListener` tests untouched and still passing.
- Task 2 checkpoint resolved: the four ambiguous territories (GI, IM, JE, GG) stay outside `CONSENT_REGIONS` per the developer's explicit choice of option a — no code change required since Task 1 already implemented the default.
