## Phase Goal

Every visitor is measured again - non-EEA/UK visitors are captured without depending on the Google
CMP, EEA/UK visitors keep the exact TCF gate, and the OPS-01 gate can never again pass on
pre-deploy data.

> **Planner note (MVP mode):** the ROADMAP Goal line for this phase is quoted verbatim above. It is
> not written in "As a / I want to / so that" form, and no user story has been invented in its
> place. If the user-story framing is wanted, run `/gsd mvp-phase 2.1` before execution - it is a
> documentation shape, not a blocker for this hotfix.

<objective>
Restore PostHog capture for every visitor the consent gate was never meant to stop, without
loosening the gate for anyone it was meant to stop.

Today `cookieless_mode: "on_reject"` puts posthog-js into PENDING, and in 1.360 PENDING means every
`capture()` is dropped - not queued, not sent cookieless, dropped. The only escape is
`opt_in_capturing()`, which the provider calls solely from a `__tcfapi` callback that Google's CMP
never fires for a fresh visitor. Result: ~99.9% of capture has been gone since 2026-09-06.

This plan moves the region decision server-side (D-01), delivers it through a single `/api/geo`
Route Handler that changes no page's rendering mode (D-02), pins the region set to exactly what the
CMP targets (D-03), opts non-consent-region visitors in with no CMP dependency (D-04), keeps the
EEA/UK TCF flow exactly as it is (D-05), extracts the merge of the two into one pure unit-tested
function (D-06), and tags every event with the path that admitted it (D-07).

Purpose: make ROADMAP success criteria 1, 2 and 3 true in code, verified by unit tests, ready for
the preview netlog proof in 02.1-03.
Output: `lib/geo.ts`, `app/api/geo/route.ts`, their tests, a new pure function in `lib/consent.ts`,
and a rewired `app/components/PostHogProvider.tsx`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| visitor browser -> `/api/geo` | An untrusted client can call the endpoint directly and can set arbitrary request headers before Vercel's edge overwrites the geolocation family. |
| Vercel edge -> Route Handler | The geolocation headers are attached by the platform; the handler trusts the platform, not the client. |
| `/api/geo` response -> shared caches | A per-visitor classification travelling back through any CDN or proxy on the path. |
| posthog-js -> PostHog ingest | Events leave the browser only once the consent gate has resolved; this is the boundary MONY-01 protects. |
