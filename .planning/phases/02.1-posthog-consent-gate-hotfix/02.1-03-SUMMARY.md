## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] The literal D-10 netlog command produced a false negative and had to be diagnosed and corrected before the gate could pass**
- **Found during:** Task 2 (the netlog proof)
- **Issue:** Running the bare command exactly as specified in `02.1-RESEARCH.md`/`02.1-VALIDATION.md`/the plan's interfaces block produced zero `/ingest/e` or `/ingest/i/v0/e` requests across five separate attempts (varying profile freshness, real-time waits up to 12s, `--virtual-time-budget` up to 25000ms, and full CDP-level console/network instrumentation) — even though independent checks confirmed the actual application code was working correctly (a hand-crafted `curl` POST to `/ingest/e/` succeeded; CDP console logging on a throwaway debug-logged redeploy showed `isConsentRegion:false` resolving, `applyOutcome` flipping `isOptedOut()` from `true` to `false`, and `ph.capture("$pageview")` being called with `isOptedOut()` already `false`). Root cause: `posthog-js`'s built-in bot/crawler filter (`_is_bot()`, gated by `opt_out_useragent_filter` which defaults to `false`/on) blocklists the literal substring `"headlesschrome"`, which Chrome's own headless mode reports in its default `navigator.userAgent`. The filter silently drops the entire body of `capture()` with no error and no console output — indistinguishable from the outside from the consent bug this plan exists to fix.
- **Fix:** Re-ran the netlog command with `--user-agent` overridden to a standard desktop Chrome string (identical version, `Headless` removed), fresh profile, same bounded `perl alarm` wrapper — otherwise unchanged. This produced 3 distinct capture requests immediately.
- **Files modified:** none (test invocation only; no application code changed for this fix)
- **Verification:** `grep -oE '"url":"[^"]*/ingest/(e|i/v0/e)/[^"]*"' <netlog>` returned 12 matching lines (3 distinct requests) against the recorded production baseline of 0
- **Committed in:** `c99b044` (Part 4 records the finding, the corrected command, and the follow-up)
