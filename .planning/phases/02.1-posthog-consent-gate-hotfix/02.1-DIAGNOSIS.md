# Phase 2.1 — PostHog Consent Gate Hotfix: Diagnosis

**Found:** 2026-09-14, while re-wiring the PostHog MCP to project 337485 (ParseForge).
**Severity:** Live production regression. PostHog capture ~99.9% down since the Phase 1 prod deploy (2026-09-06 ~22:00). Both Phase 1 and Phase 2 OPS-01 "PostHog verified" gates passed on pre-deploy data.

The six Phase 1/2 custom events (`theme_changed`, `consent_resolved`, `consent_unavailable`, `timeline_viewed`, `timeline_filter_used`, `timeline_error`) have **never** been ingested. All 15 pre-existing custom events are present in the taxonomy.

### 2. Who still gets captured

Last 7 days: 22 events / 6 persons. **18 events, 5 persons are returning visitors** (`person.created_at` < 2026-09-07). Countries: PL, DE, SE, UA, AU — no US on a WoW Classic site. Consistent with "only visitors holding a pre-existing `__ph_opt_in_out_*` opt-in cookie still capture".

### 3. Live headless-Chrome netlog (fresh profile, 2026-09-14)

`https://parseforge.gg/` loaded: `/ingest/array/<token>/config.js`, `/ingest/static/web-vitals.js`, and `fundingchoicesmessages.google.com/i/pub-…` all fetched. **Zero requests to any `/ingest/e/*` or `/ingest/i/v0/e/*` capture endpoint.** SDK and CMP load; nothing is ever sent.

Site itself is healthy (HTTP 200, ~0.5s). CSP is `report-only`, so it blocks nothing.

### 4. Mechanism (posthog-js 1.360.0, `dist/module.js`)

```js
isOptedOut() {
  return this.config.cookieless_mode === "always"
    || this.consent === DENIED
    || (this.consent === PENDING
        && (this.config.opt_out_capturing_by_default
            || this.config.cookieless_mode === "on_reject"));
}
```

`app/components/PostHogProvider.tsx` sets `cookieless_mode: "on_reject"`. Therefore **PENDING ⇒ opted out ⇒ every `capture()` is dropped** (not sent cookieless — dropped). Capture only resumes after `ph.opt_in_capturing()`, which the provider calls solely from the `startConsentListener` callback on `"opt-in-full"` / `"opt-in-non-eea"`. That callback depends on Google Privacy & Messaging's `__tcfapi` invoking our listener with a resolved payload. For fresh visitors it demonstrably does not (see §3) — most likely because `window.__tcfapi` is not present at `loaded` time (the page ships the FC loader but not the standard `__tcfapi` stub/locator snippet), so no listener is ever attached; the 3 s `CMP_TIMEOUT_MS` then fires `"pending"`.

The designed failure signal, `ph.capture("consent_unavailable", …)`, is itself emitted while PENDING, so it is dropped too. The fail-closed path was unobservable by construction — which is why the regression went unnoticed for a week.

## Decision (developer, 2026-09-14)

- **Fix approach:** server-side geo. Read Vercel's `x-vercel-ip-country` (and `x-vercel-ip-country-region` for UK/EEA edge cases) in the root layout, pass an `isEEA` (EEA + UK + CH?) flag to the client. Non-EEA → `opt_in_capturing()` immediately at `loaded`, with no CMP dependency. EEA/UK → keep the TCF gate exactly as it is (`on_reject` semantics, replay only on full opt-in).
- **Tracking:** urgent Phase 2.1 inserted before Phase 3.
- **Gate hardening:** OPS-01 (`docs/OPS-01-SHIP-GATE.md`) must require a *post-deploy live-traffic* check — e.g. "≥ N `$pageview` events from ≥ 2 non-EEA countries within 60 min of the prod deploy" — rather than confirming event definitions exist.

## Scope notes for planning

1. `app/components/PostHogProvider.tsx` — accept `isEEA` prop; opt in immediately when false; keep `consent_resolved` / `consent_unavailable` emission but ensure they are sent *after* opt-in where applicable (a PENDING-time capture is silently dropped — consider `send_instantly` after `opt_in_capturing`).
2. `app/layout.tsx` (server) — read `headers()` for `x-vercel-ip-country`; EEA/UK list as a `lib/` constant with a unit test; unknown/absent header → treat as EEA (fail closed) but *log* a server-side metric via `lib/observability.ts`.
3. `lib/consent.ts` — unchanged semantics for EEA; add a `consent_gate_path` property (`"geo-non-eea" | "tcf" | "timeout"`) so the fix is measurable.
4. Tests: `lib/consent.test.ts` extension + a new `lib/geo.test.ts`.
5. OPS-01: amend `docs/OPS-01-SHIP-GATE.md` with the live-traffic check; run it for real after this deploy.
6. Retro note: Phase 1 & 2 VERIFICATION docs should get an addendum saying their PostHog criterion was not actually met until 2.1.
