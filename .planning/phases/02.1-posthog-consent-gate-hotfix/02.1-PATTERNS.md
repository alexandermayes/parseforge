## Pattern Assignments

### `lib/geo.ts` (new)

**Analog:** `lib/consent.ts` (whole file, esp. lines 1-5, 45-46, 62-79)

**File-header comment convention** (`lib/consent.ts` lines 1-4):
```typescript
// Pure TCF v2.2 consent decision logic, in the style of lib/url-parser.ts:
// typed input, narrow return, no throwing. `window.__tcfapi` is a third-party
// global this project doesn't control, so every field on the payload it hands
// us is optional and we resolve unknowns to "pending" rather than guessing.
```
`lib/geo.ts` should open with an equivalent comment naming its source of truth (Google's AdSense support doc region list) and its fail-closed rule.

**Constant-with-JSDoc pattern** (`lib/consent.ts` line 46):
```typescript
/** How long to wait for a TCF event before failing closed to "pending". */
export const CMP_TIMEOUT_MS = 3000;
```
Use the same shape for `CONSENT_REGIONS`: a single exported, documented constant (`Set<string>` per RESEARCH's "Don't Hand-Roll" table — O(1) `.has()`, no regex).

**Pure decision function pattern** (`lib/consent.ts` lines 62-79, `deriveConsentAction`):
```typescript
export function deriveConsentAction(
  tcData: TcfConsentData | null | undefined,
): ConsentAction {
  if (!tcData || tcData.gdprApplies === undefined) return "pending";
  if (tcData.gdprApplies === false) return "opt-in-non-eea";
  ...
}
```
Model `isConsentRegionCode(code: string | null): boolean` the same way: typed input (including `null` for the missing-header case), narrow boolean return, no throwing, comment explaining the fail-closed default inline (mirrors D-03's "unknown/missing header ⇒ consent region").

**Error handling:** none needed — pure function, no I/O, no try/catch (matches `deriveConsentAction`, which also has none).

**Analog:** itself — extend the existing pure-function + type pattern already in the file rather than introduce a new style.

  | "opt-in-full"

### `app/components/PostHogProvider.tsx` (modified)

**Current structure being replaced** (lines 27-100): `posthog.init(...)` currently lives inside `PostHogProvider`'s own `useEffect`, and its `loaded` callback's `switch` (lines 63-93) only knows about `ConsentAction` from `startConsentListener`. Per RESEARCH Pattern 2 and D-04, this must become:

3. The `loaded` callback's `switch` becomes a **thin call into the new pure function in `lib/consent.ts`** (D-06) rather than the current five inline branches — the existing branch bodies (`ph.opt_in_capturing()`, `ph.startSessionRecording()`, `ph.capture("consent_resolved", ...)`, `ph.capture("consent_unavailable", ...)`) are the concrete SDK calls the new pure function's result should map to; they do not change, only who decides which one fires.

## Shared Patterns

### Errors-as-data / no-throw discipline
**Source:** `lib/observability.ts` lines 16-25 (`logEvent`'s try/catch), `lib/consent.ts` (no exceptions anywhere in the pure functions)
**Apply to:** `lib/geo.ts`, `app/api/geo/route.ts` — neither should throw; `logEvent("geo_header_missing")` must be wrapped by `logEvent`'s own internal try/catch (already true — callers don't need their own try/catch around `logEvent`).
```typescript
export function logEvent(event: string, props: LogProps = {}): void {
  try {
    console.log(JSON.stringify({ metric: event, ...props }));
  } catch {
    // Observability must never break a request.
  }
}
```

### Pure-function-plus-colocated-test pattern
**Source:** `lib/consent.ts` + `lib/consent.test.ts`
**Apply to:** `lib/geo.ts` + `lib/geo.test.ts`, and the new merge function added to `lib/consent.ts` + `lib/consent.test.ts` — typed input (including the `null`/missing case), narrow return type, no side effects, one `describe` block per function, one `it` per branch.

### `@/` absolute imports, never relative
**Source:** every file read this session (`app/api/report/[code]/route.ts` line 2-7, `app/components/PostHogProvider.tsx` line 7)
**Apply to:** all new/modified files — `app/api/geo/route.ts` imports `@/lib/geo`, `@/lib/observability`; `PostHogProvider.tsx` imports `@/lib/consent`.

### Route Handler response headers for privacy-sensitive per-visitor data
**Source:** no existing analog sets `Cache-Control` explicitly (new pattern, sourced from RESEARCH.md D-02/Pattern 1, not from an existing file)
**Apply to:** `app/api/geo/route.ts` only — `Cache-Control: private, no-store`, no cookie set. Flag to planner: this is NOT copied from an existing route; it's a first-of-its-kind requirement in this codebase.
