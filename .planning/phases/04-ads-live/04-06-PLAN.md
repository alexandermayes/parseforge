|----------|-------------|
| Vercel SSO → automated preview checks | without the bypass, every automated fetch reads a redirect page instead of the app |
| preview browser → third-party ad and analytics hosts | the network log is the only place the real request behaviour is observable |
| captured evidence → a committed, permanent document | anything pasted into the ship gate is public repository content forever |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-28 | Repudiation | a gate greened against an SSO redirect rather than the real page | high | mitigate | Every preview fetch supplies the bypass and every recorded row carries its status and content type; a redirect status is visible in the recorded evidence rather than silently passing |
| T-04-29 | Repudiation | recording "the code gates the script" as if it were "the browser did not request it" | high | mitigate | The two-direction netlog is mandatory: a non-zero count for the admitted run and a zero count for the fail-closed run, each with its command captured |
| T-04-30 | Information Disclosure | the automation-bypass secret leaking into committed evidence | high | mitigate | The secret is confirmed non-empty by length only and never printed; the gate greps the recorded section for a bypass value and fails on a hit; the pulled env file is deleted after use |
| T-04-31 | Tampering | posthog-js's headless-Chrome bot filter producing a silent zero and being read as a gate result | medium | mitigate | The browser run overrides the user agent, per the Phase 2.1 finding recorded in Part 4; the netlog's ad-host count is independent of PostHog either way |
