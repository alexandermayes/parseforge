<objective>
**Phase tracer.** Wire one reserved, consent-gated ad slot end-to-end — from the consent decision the
app already makes, through a new gate module, through a client component that reserves its exact box,
to a real AdSense script injection and a PostHog event — on one route, one position, one path. Then
give the phase its machine check (`protected-elements`) and its two supporting surfaces (CSP hosts,
`/ads.txt`) so the slice is production-quality rather than a prototype.

**User story (MVP framing):** **As a** ParseForge visitor, **I want to** reach the raid audit page
and have it look and behave exactly as it did before ads existed, **so that** an ad box appearing
below the content never costs me the thing I came for.

After this plan a real user can do something they could not before: load `/tbc-audit` on a build with
ads switched on and see a stable, reserved ad position that fills without moving anything — and an
EEA/UK visitor who rejected can load the same page and have the ad script never touch the network.

Purpose: prove the whole architecture on one path before three more slots ride on it. The expensive
mistake this ordering prevents is discovering, after four placements are committed, that the ad gate
cannot read the consent decision without forking it.
Output: `lib/ads.ts`, `app/components/AdSlot.tsx`, the consent gate-path publisher, one live slot,
`/ads.txt`, CSP report-only ad hosts, and the extended protected-elements gate.

**1. `lib/consent.ts` — publish the resolved gate path (the promote decision).**
Add, below the existing `deriveConsentGateOutcome`, three exports and one module-level variable:
`publishConsentGatePath(path: ConsentGatePath): void`, `getConsentGatePath(): ConsentGatePath | null`,
and `subscribeConsentGatePath(cb: (path: ConsentGatePath) => void): () => void`. The publisher stores
the path, notifies every current subscriber, and is a no-op when re-published with the same value.
`subscribeConsentGatePath` calls its callback synchronously with the already-known path if one has
been published, then on every subsequent change; it returns a disposer. Keep `deriveConsentGateOutcome`
pure — it must not publish; publishing is the executor's job, not the decision function's. Add a doc
comment saying, in one sentence, that this is the single published consent decision and that any
future consumer subscribes here rather than deriving its own.

**2. `app/components/PostHogProvider.tsx` — publish, do not re-derive.**
Two surgical changes and nothing else:
  - Move the PostHog-key guard. The effect currently returns immediately when `POSTHOG_KEY` is empty,
    which would leave the consent decision unpublished and therefore leave ads permanently off on any
    deployment without a PostHog key (previews, for one). Delete that opening early return and instead
    guard each `posthog.*` call inside `applyOutcome` so the SDK is untouched when there is no key.
    The geo fetch, the fail-closed catch, `applyDecision` and the TCF listener now always run.
  - Inside `applyOutcome`, immediately after the existing `posthog.register({ consent_gate_path: ... })`
    line, call `publishConsentGatePath(outcome.gatePath)`. Place it after the register call so the
    documented ordering (gate path registered before any capture) is unchanged.
Do not touch `capturedGatePathRef`, the dedupe behaviour, the call order, the module-scope `init`, or
the geo-endpoint body validation. There must still be exactly one fetch of the geo endpoint and
exactly one CMP event-listener registration in the entire client bundle after this change.

**3. `lib/ads.ts` — the gate, the slot table, and the loader.**
Module header comment in the style of `lib/consent.ts` line 1-4: typed input, narrow return, no
throwing. Exports:
  - `export type AdSlotId` — a string union. This task declares only `"tbc-audit-end"`; 04-05 adds
    `"tbc-audit-mid"`, `"analyze-mid"` and `"analyze-end"`.
  - `export interface AdSlotSpec { route: string; base: { width: number; height: number }; md: { width: number; height: number }; boxClass: string; unit: string; collapsible: boolean }`.
  - `export const AD_SLOTS: Record<AdSlotId, AdSlotSpec>` — for `tbc-audit-end`: route `/tbc-audit`,
    base 300x250, md 336x280, a `boxClass` of static Tailwind size literals encoding those four
    numbers with the md variants under the `md:` prefix, `unit` set to the placeholder string
    `PENDING` until 04-05's AdSense checkpoint supplies the real unit id, and `collapsible` true.
    Keep the class literals as whole static strings so Tailwind's scanner sees them; never build a
    class name by concatenation.
  - `export function shouldLoadAds(gatePath: ConsentGatePath | null): boolean` — true for exactly the
    two admitted paths of D-07, false for everything else including null. Same narrow, non-throwing,
    fail-closed shape as `deriveConsentAction`'s own unknown-input guard.
  - `export function adsConfigured(slotId: AdSlotId): boolean` — reads
    `process.env.NEXT_PUBLIC_ADS_ENABLED` (must equal the string `1`) and
    `process.env.NEXT_PUBLIC_ADSENSE_PUB_ID` (must be non-empty), and requires the slot's `unit` not
    to be the placeholder.
  - `export function normalizeRoute(pathname: string): string` — strips any query string and maps a
    path under the analyze route to the literal route pattern `/analyze/[reportCode]`; returns other
    paths unchanged. This is the only value that may be used as the `route` property on an ad event.
  - `export function loadAdSenseScript(): Promise<boolean>` — idempotent: on first call it appends one
    `script` element to `document.body` (never to `document.head`, never via `next/script`, never at
    the app root) whose src is the AdSense SDK URL for the configured publisher id, with `async` and
    `crossOrigin` set to anonymous, and resolves true on load / false on error. Every later call
    returns the same promise. A false resolution is how an ad blocker is detected.
Do NOT add an npm dependency for any of this — 04-RESEARCH.md's Standard Stack section is explicit
that no package understands this project's gate, and CLAUDE.md's "reuse before adding" rule applies.
**Deliberate divergence from 04-RESEARCH.md Pattern 2, recorded here:** research proposed mounting the
SDK with `next/script` in `app/layout.tsx` next to the CMP script. That pattern loads the script for
every visitor, which D-07 forbids and D-06's "no head ad script" rules out. The loader injects the tag
itself, from the client, only after the gate admits.

**4. `app/components/AdSlot.tsx` — the client component.**
`"use client"`. Props: `{ id: AdSlotId; className?: string }`. Behaviour:
  - If `adsConfigured(id)` is false, return null. A build with ads switched off is byte-identical in
    layout to the pre-ad build, which is what makes D-08's flag a true removal and keeps the Part 6
    baseline comparable.
  - Otherwise render an outer `div` carrying `data-ad-slot={id}`, the spec's `boxClass`, `mx-auto`,
    and inline `width`/`height` style values in pixels taken from the spec's `base` box. Use explicit
    width and height — never a lower-bound height property — so the machine check can assert exact
    dimensions rather than a floor.
  - On mount, subscribe via `subscribeConsentGatePath`. When a path arrives and `shouldLoadAds(path)`
    is true, schedule admission on `requestIdleCallback` with a 2000 ms timeout, falling back to
    `setTimeout` where the API is absent; clear it on unmount. When the path is one of the two refused
    ones, mark the slot terminally refused: if the spec is `collapsible`, and only then, render null
    from that point on — that is safe solely because a collapsible slot has no content below it in
    document order and therefore shifts nothing. A non-collapsible slot keeps its reserved box empty
    forever. Never change a box's dimensions after first paint.
  - On admission: `await loadAdSenseScript()`. If it resolves false, capture `ad_slot_blocked` and
    stop. If true, render the `ins` element inside the box with the AdSense class, `display: block`
    and 100% width/height, the publisher id and the slot's unit id as its data attributes, then push
    an empty configuration object onto the global ad queue exactly once per mount. Do not set any
    auto-sizing format attribute — a unit that sizes itself renders at zero height until it fills,
    which is the single most-cited cause of ad layout shift and is what D-04 exists to prevent.
  - Capture `ad_slot_requested` at push time. Then observe the `ins` element's ad-status data
    attribute with a `MutationObserver` (disconnected on unmount, and after a 10 s ceiling) and
    capture `ad_slot_filled` or `ad_slot_empty` exactly once based on its value. Every capture carries
    exactly three properties: `route` from `normalizeRoute(usePathname())`, `slot_id` from the id, and
    `consent_gate_path` from the resolved path. Nothing else — no report code, no player name, no URL.
  - Declare the two browser globals this file needs (the ad queue array and the idle-callback pair) in
    a local `declare global` block in the style `lib/consent.ts` already uses for the CMP global.
    Do not register a CMP event listener here and do not fetch the geo endpoint here.
