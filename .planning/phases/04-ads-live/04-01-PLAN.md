the RPGLogs commercial-use approval request (R0-1), and the pre-ad Core Web Vitals baseline plus the
written rollback trigger (MONY-03 / D-09, D-10, D-11).

**User story (MVP framing, from the ROADMAP goal):** **As a** ParseForge visitor, **I want to**
keep the paste-and-analyze flow exactly as fast as it is today, **so that** the site can earn ad
revenue without the thing I came for getting measurably worse.

consent-gated ad slot wired end-to-end). This plan exists first because two locked decisions impose a
hard pre-code ordering: D-09 requires the baseline table to be written "before the first ad commit",
and D-13 names R0-1 "the phase's first task". It produces no product code and no horizontal layer.

Purpose: an ad deploy with no baseline cannot be rolled back on evidence, and an ad deploy with no
recorded approval is a Terms-of-Service breach (`PARSEFORGE-RANKINGS-SPEC.md` §2.1).
Output: two dated ToS/API-docs captures, a populated approval Thread table, and `docs/OPS-01-SHIP-GATE.md` Part 6.
</objective>
