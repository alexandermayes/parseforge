`lib/wcl-client.ts` internals the tests must drive without changing its signature:
- `getAccessToken` reads `WCL_CLIENT_ID` and `WCL_CLIENT_SECRET` from `process.env` and throws a plain Error
  naming both when either is absent; it caches at module scope and in `kv-cache` under the key `wcl:token`.
- A 401 response calls `clearAccessToken`, which clears both the module cache and the `kv-cache` entry, then
  continues to the next attempt — the refresh-and-retry path.
- `MAX_RETRIES` is 3; `RETRY_BACKOFF_MS` is `[1000, 2000, 4000]`; `REQUEST_TIMEOUT_MS` is 30000.
- `isRetryable(status)` is true for 429 and for any status at or above 500; a retryable status on the last
  attempt throws `WCLError` with kind `rate_limited` for 429 and `upstream` otherwise.
- An `AbortError` from the timeout controller throws kind `timeout` on the last attempt.
- `classifyGraphQLError` lowercases the joined error text: "does not exist", "not found" or "no such report"
  gives `not_found`; "permission", "private", "not authorized", "do not have" or "access" gives `private`;
  anything else gives `upstream`.
- A module-level query cache keyed on query plus variables returns early on a hit — successive identical
  calls inside one test file will not re-hit the stubbed fetch, so each scenario must vary its query string
  or its variables.
