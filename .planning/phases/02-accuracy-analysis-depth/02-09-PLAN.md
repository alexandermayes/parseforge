## Phase Goal

Raiders get verifiably correct analysis plus the per-fight depth competitors already offer.

<objective>

dated sign-off.

regenerated game-data pipeline, and a regression net under three engines. ROADMAP success criterion 5 is not

confirmation each time. Phase 1's 01-09 set the precedent: offer a preview, propose the production deploy as
a decision, and act on the answer.

Purpose: close OPS-01 for Phase 2 and ship the phase.
Output: a fully evidenced Phase 2 section in `docs/OPS-01-SHIP-GATE.md`, a production deploy the developer
approved, and post-deploy Search Console and PostHog results recorded.
</objective>

The six-step gate this plan runs, from `docs/OPS-01-SHIP-GATE.md`:
1. Local gate — `npx tsc --noEmit`, `npm run lint`, `npm test`, `npm run theme-parity`, `npm run token-audit`.
   Evidence: captured command output, exit codes and summary lines.
2. Both-theme route sweep — every route with a `page.tsx` under `app/`, in Light and Dark. There is no
   automated visual-regression harness in this project, so this manual pass is the only coverage. Phase 1
   established the live route count as 11.
3. SEO invariants — `npm run seo-invariants`, which diffs the local render's title, canonical, robots,
   description, og:title, og:image and sorted JSON-LD type list against production at the same path.
   Evidence: the printed route table.
4. PostHog instrumentation — every new user-facing interaction has exactly one `posthog.capture` call site,
   grep-verifiable pre-deploy; post-deploy, confirm the event appears in the project's event definitions.
5. Search Console — post-deploy, URL-inspect the affected routes and confirm indexability and metadata are
   unchanged. Evidence: the inspection result per route, `no-data` when Google has not crawled it yet.
6. Sign-off — dated.

Document conventions that must be honoured: a row may only be marked passing when the evidence that produced
it is recorded alongside it; route rows are ordered lexicographically by path so two runs are diffable; a
second check on an existing route extends that route's row rather than adding a duplicate.

`vercel deploy --prod --scope loot-list-plus --yes` — project `parseforge` under team `loot-list-plus`,
aliased to parseforge.gg. A preview deploy is the same command without `--prod`.

PostHog events shipped this phase: `timeline_viewed` and `timeline_error` (02-02),
`timeline_filter_used` (02-05), plus new properties on the existing `analysis_complete` (02-07).

STATE.md's carried-forward follow-ups for this gate: re-check the `theme_changed` and `consent_resolved`
event definitions, which recorded no-data at the Phase 1 gate because the PostHog MCP connection dropped.

Routes affected this phase: `/analyze/[reportCode]` only. No route was added — the Timeline tab lives behind
the existing `ptab` search param and the canonical stays parameter-free (D-01).
