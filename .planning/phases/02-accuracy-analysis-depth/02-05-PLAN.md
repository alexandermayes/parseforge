Extend `lib/timeline-engine.ts` so the row kinds the contract already declares are actually emitted.

**Derive the idle threshold from the player, not from a table of class constants.** After the cast rows
are sorted, compute the gaps between consecutive casts, take their median, and set `idleThresholdMs` to
the larger of 2000 and three times that median, rounded to a whole millisecond. Document the reasoning in
a comment: three times a player's own median cast interval is long enough that a caster with a 1.5 second
rhythm and a melee with a 300 millisecond rhythm each get a threshold proportional to how they actually
play, and the 2000 millisecond floor stops a very fast rotation from flagging every ordinary
global-cooldown boundary as idle. A sequence with fewer than two casts has no gaps, so the threshold falls
back to the floor and no idle row can be emitted.

**Emit an idle row for every gap above the threshold**, inserted between the two cast rows that bracket
it, with `kind: "idle"`, `fightTimeMs` equal to the earlier cast's time, and `idleMs` equal to the gap.
Never emit an idle row before the first cast or after the last: the log describes the space between casts,
and pre-pull or post-death silence is not a decision the raider made mid-fight.

**Emit at most one death row.** Take the death events the route passes in, keep only those whose source is
this player, take the earliest, and emit one row with `kind: "death"` and `fightTimeMs` equal to that
event's timestamp minus the fight's start time — the same subtraction `lib/raid-overview-engine.ts` line
253 already performs. Merge it into the row array by chronological position rather than appending it, so
the log reads as a single ordered stream. Extend `TimelineEngineInput` with the death-event array; the
route already fetches it through the `deathEvents` field on the timeline query.

**Keep `castCount` counting cast rows only**, so the truncation notice and the PostHog event report the
number of casts and not the number of rendered bands.
