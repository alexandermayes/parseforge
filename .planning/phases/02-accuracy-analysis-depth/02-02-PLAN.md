## Phase Goal

Raiders get verifiably correct analysis plus the per-fight depth competitors already offer.

<objective>
Ship the phase's headline user-visible win: a raider opens a Timeline tab on a player's analysis and
reads, in order, what that player actually cast during that fight.

This plan leads with one tracer task that wires a single path through every layer the timeline will
ever touch — GraphQL query, API route with pagination, pure engine, lazy client hook, sub-tab, log
component — and proves it with a real end-to-end check against the fixtures recorded in 02-01. The
architecture the tracer establishes is the architecture plan 02-05 expands into idle gaps, a death
marker, per-ability filter chips and virtualisation.

Purpose: close ACC-03's success criterion — "User can open a per-fight cast timeline for a player in
an analyzed report and read what that player actually cast, in order" — on the earliest, freshest
context of the phase, so an architectural dead-end surfaces after one commit rather than five.
Output: a working Timeline tab, a tested pure timeline engine, and a rate-limited, cached, page-capped
`/api/timeline` route.
</objective>

**`lib/timeline-engine.ts`** — a pure, synchronous, JSON-serialisable transform, mirroring
`buildRaidOverview`'s shape. Export `TimelineEngineInput` and
`buildCastTimeline(input: TimelineEngineInput): CastTimelineResult`. The input bag carries
`castEvents: WCLCastEvent[]`, `castTable: WCLCastEntry[]`, `actors: Array<{ id: number; name: string;
type: string; subType?: string }>`, `fight: { name: string; startTime: number; endTime: number }`,
`playerName: string`, `sourceId: number` and `truncated: boolean`.

The transform: build a guid-to-entry map from `castTable` so each event resolves a display name and
an `abilityIcon` — the aggregated Casts table is where those live, the event stream carries only ids.
Apply `buildRankedNames` over the cast-table entries so abilities sharing a base name across ranks
read as they already do on the Casts tab. Drop any event whose ability resolves to an entry that
`isJunkSpell` rejects, and drop any event whose ability has no cast-table entry at all (an id the
aggregated table does not list is not a cast this player made in this fight). Sort the surviving
events ascending by timestamp. Emit one `TimelineRow` per event with `kind: "cast"`, `fightTimeMs`
equal to the event timestamp minus `fight.startTime`, the resolved `abilityGameID`, `abilityName` and
`abilityIcon`, and a `targetName` resolved from the actor list by target id — the literal `Self` when
the target id equals `sourceId`, and left undefined when the event carries no target so a surface can
render an em dash. Build `abilityCounts` from the unfiltered surviving events, one entry per distinct
ability with its total occurrence count, sorted by count descending. Set `castCount` to the number of
emitted cast rows, `truncated` from the input, `encounterName` from `fight.name`, `fightDuration` to
`fight.endTime - fight.startTime`, and `idleThresholdMs` to 0.

Emit only `kind: "cast"` rows in this task. Plan 02-05, in wave 3 of this same phase, populates the
`idle` and `death` row kinds and computes a real `idleThresholdMs`; the `kind` discriminator, the
`idleMs` field and the `idleThresholdMs` field already exist in the contract precisely so that
addition needs no shape change to the engine, the route, the hook or the component.

**`lib/timeline-engine.test.ts`** — drive it entirely from `lib/__fixtures__/demo-timeline-casts.json`.
Assert: rows come back in ascending `fightTimeMs`; the first row's `fightTimeMs` is small relative to

every row's `abilityName` is a non-empty string; a synthetic event whose ability id resolves to a junk
entry is excluded; an event whose target id equals `sourceId` produces the literal target name `Self`;
an event with no target id produces an undefined `targetName` rather than a dropped row;
`abilityCounts` sums to `castCount`; and `abilityCounts` is ordered by descending count.

**`app/api/timeline/route.ts`** — copy `app/api/analyze/route.ts`'s skeleton exactly. Export an async
`POST`. `parseBody` with the three required fields, then `checkRateLimit(request, "timeline")`, then
`isValidReportCode(reportCode)` returning `badRequest("Invalid report code.")` and a
`Number.isInteger` check on both ids returning `badRequest("Invalid fight or source id — expected
integers.")`. Only then build the cache key. Wrap the body in
`cachedApiHandler(\`timeline-${reportCode}-${fightId}-${sourceId}\`, ...)`.

Inside: run `TIMELINE_CASTS_QUERY` through `wclQuery`. If the returned fights array is empty, return
`NextResponse.json({ error: "Fight not found" }, { status: 404 })`, matching the existing route
verbatim. If the requested source id is absent from the master actor list, return the same shape with
the message `Player not found in fight`. Accumulate `castEvents.data`, then loop with
`TIMELINE_CASTS_PAGE_QUERY` while the response returns a next-page timestamp, passing it as the next
call's `startTime`. Declare a module-level `const MAX_TIMELINE_PAGES = 20;` with a comment recording
that the cap is a required denial-of-service bound and not a nicety: without it a crafted fight id
could force unbounded WCL query volume against a shared API quota. Set `truncated` to true when the
loop exits because the cap was reached rather than because pagination ended. Call `buildCastTimeline`
and return its result. Do not catch WCL errors here — `cachedApiHandler` already maps them through
`errorResponse`, which is what keeps the classified `not_found` / `private` / `rate_limited` /
`timeout` / `upstream` kinds intact.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> POST /api/timeline | Untrusted report code, fight id and source id cross into the server |
| /api/timeline -> shared Redis cache | Request-derived values compose a cache key in a keyspace shared across all visitors |
| /api/timeline -> WCL GraphQL API | One request can fan out into many upstream queries against a shared third-party quota |
| /api/timeline -> browser | Upstream error text could reach the client if not classified |
