## Phase Goal

Raiders get verifiably correct analysis plus the per-fight depth competitors already offer.

<objective>
Make the generated modules the runtime source of truth, and produce the standing artifact that proves the
regeneration diff was reviewed.

Plan 02-03 built the pipeline and generated three era modules. This plan verifies consumable names against
client data, composes everything into the four maps the engines already import, cuts `lib/cla-constants.ts`
down to a thin re-export, and emits `docs/GAME-DATA-AUDIT.md` — the same standing-artifact pattern
`docs/TOKEN-AUDIT.md` established in Phase 1.

site across `lib/analysis-engine.ts`, `lib/cla-engine.ts`, `lib/raid-overview-engine.ts` and
`app/api/analyze/route.ts` keeps working without edits.

Purpose: close ACC-01 and its success criterion — every enchant, gem and consumable ID traces to a
wago-regenerated data file, with the regeneration re-run this phase and the diff reviewed (D-09, D-11, D-12).
Output: a generated consumables module, a composition index, a 178-row curation registry moved into the one
overrides file, a thin `lib/cla-constants.ts`, and `docs/GAME-DATA-AUDIT.md`.
</objective>
